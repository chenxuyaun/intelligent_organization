# 时效性记忆对照：公开 GitHub 规则（2026-11-17）

## 研究问题

当组织记忆把“何时生效、适用谁、旧规则是否已被替代”写清楚时，模型能否比直接检索普通资料片段更准确、更好地解释当前规则？这次实验只看回答和引用，不代表真实组织成效。

## 实验设置

- 使用 5 个公开 GitHub 规则变更问题：组织 PAT 默认、GraphQL 支持、PAT 过期策略、PAT 审批 API、创建仓库所需最小权限。
- 两组使用相同问题、DeepSeek Flash、组织模式、项目提示词和隔离数据库。
- **原始组**把来源摘要作为普通资料片段；**结构化组**把适用时间、适用对象和新旧规则关系明确写入资料正文与 `applies_to` 字段。
- 每组先跑 5 个问题。初次有 2 条模型输出为空（原始组的过期策略、结构化组的组织 PAT 默认）；两条各重试一次后都得到非空回答。最终可读回答为每组 5/5，但首轮空输出率是 2/10，且 `origin=live` 并不能保证回答非空。
- 运行只写入 `%TEMP%` 下两套隔离数据库；没有使用或更改 4173 主服务数据库中的工单、审核或知识卡，也没有真实组织资料。

## 初步观察

| 问题 | 原始资料组 | 时效结构化组 | 初步判断 |
|---|---|---|---|
| 组织 PAT 看不到组织/仓库范围 | 提到了 2025 GA 默认和管理员核查，但较少解释创建时应如何选资源归属 | 清楚区分 beta 与 GA，指出选择组织作为 Resource owner，并核查组织策略 | 结构化组更可操作 |
| fine-grained PAT 能否调用 GraphQL | 答对已支持，但对 owner 规则较保守 | 答对，并明确新旧规则分界与 owner 匹配 | 两组方向正确，结构化组时间边界更清楚 |
| PAT 可否永不过期 | 回答无法从片段确认组织默认期限 | 区分个人项目可无过期与组织/企业默认 366 天策略 | 结构化组更完整 |
| 能否自动审批 PAT 请求 | 倾向 GitHub App，但表述仍较试探 | 明确 GitHub App 可通过 API/webhook 处理，PAT/OAuth app 不能调用这些 API | 结构化组更明确 |
| 创建仓库需要什么最小权限 | 认为更新后的规则片段不完整，无法确认新权限 | 给出 `repository_creation:write`，并指出旧权限范围更宽 | 结构化组更完整 |

这是定性观察，没有预先注册的打分表，也没有盲评。不能把它读成“结构化记忆必然提升 5/5”。

## 重要限制

1. 结构化组不只是多了元数据：正文、标题和标签也重新组织过，因此本实验不能把差异单独归因于 `applies_to` 字段。
2. 空回答的重试不是完全相同的检索条件：首轮后，隔离脚本把已解决的公开案例从可检索状态移开，重试主要检索规则卡。比较时应把重试标为故障复核，不能当作严格配对样本。
3. 每个问题每种条件只有一次有效回答，使用单一模型；没有组织成员盲审，也没有真实后续工单、人工修正规则或业务结果。
4. 少数结构化回答出现重复引用标签。有效引用仍指向真实来源卡，但引用格式需要单独检查。

## 对“智能组织”研究的意义

这次只看到局部证据：规则更新如果带有清楚的生效时间、适用范围和替代关系，模型更容易把“以前如此”和“现在如此”分开。它还没有证明组织具备集体判断或学习能力。

要研究集体学习，下一步应让人核对回答、修正记忆并记录由谁确认；之后用新问题检查这条已确认的记忆是否被正确复用，同时观察错误是否减少、是否需要反复解释。关键闭环是“新信息 → 人的判断 → 有时效和范围的组织记忆 → 后续复用 → 结果复核”。

## 受控复测：只改适用范围字段

为检查初测效果是否只是因为重写了资料，另做 5 组配对复测。两边的来源标题、正文、标签、来源链接、问题文本、提示词和模型完全相同；唯一不同是结构化组给来源填写 `applies_to`，原始组留空。两边各跑 5 次，共 10 次，均为 live 且输出非空。每道题两边检索到的来源编号相同。

| 问题 | 检索一致性 | 受控复测结果 |
|---|---|---|
| 组织 PAT 默认 | 两边均为 K2、K1 | 都区分了 2025 GA 与 2022 beta；结构化组更简洁，结论没有实质变化 |
| GraphQL | 两边均为 K4、K2、K3、K1 | 都答对支持 GraphQL；结构化组更明确地复述起效日期 |
| PAT 过期策略 | 两边均为 K6、K5 | 两边都没能从 96 字的检索片段确认组织默认 366 天上限；结构化组仅提示个人与组织范围不同 |
| 审批 API | 两边均误命中 K2、K4，未检索到审批资料 K7、K8 | 两边都表示依据不足；这是检索相关性问题，时间字段没有帮助找到正确资料 |
| 创建仓库权限 | 两边均为 K9 | 两边都没读到片段后半段的 `repository_creation:write`；结构化组只补充了适用日期 |

**这轮更干净的结果：**单独填写适用范围字段能帮助模型把日期说清楚，但没有改善最关键的事实遗漏。初测里结构化资料组的明显优势，很可能主要来自重排和压缩资料正文，让新规则落在模型实际收到的片段里；单靠元数据不足以弥补被截断的事实，也不能修复检索错题。

实现层能看到两个具体瓶颈：`server/retrieval.js` 的 `snippet()` 默认只把 96 个字符送进模型；审批问题的词法检索把两张无关 PAT 卡排在前面。

## 检索改进的小规模验证

在受控复测的隔离数据库上做了两处代码修改，并对过期策略、审批 API、仓库创建权限各跑原始/结构化版本一次：

- 检索片段默认上限从 96 提至 480 字符；短资料会完整送入，避免规则关键后半句被裁掉。
- 来源工单类别与当前问题类别完全一致时加 2.5 分排序权重，不过滤其他候选；返回结果另记 `category_match`，供运行记录检查。
- 6/6 次均为 live 且有非空回答。两种资料版本都能回答个人 PAT 无过期、组织资源默认 366 天限制；审批题现在召回 K7/K8，并答出审批 API 仅允许 GitHub App 使用；仓库权限题能读出 `repository_creation:write` 和 owner approval 要求。
- 这是小样本方向验证，不是通用准确率结论：仅 3 道题、每条件 1 次；类别标签来自明确整理的样本；更长文档仍可能超过 480 字符。类别相同时的排序偏置还需用真实类别分布检查。
- 本轮修改已在代码中并已重启 4173 加载；主库仍为 15 工单 / 42 运行 / 7 张 sample 卡，未新增工单或运行。

## TypeSafe / Jev 结构化判断节点（2026-11-18）

### 适合放在哪个节点

TypeSafe 官方接口接收 `state` 与带名称的结构化问题，支持 yes/no（Noul）、选项（Choice）、评分（Score）等结果；同一请求可以并行回答多个问题。它不生成给同事看的长篇处理建议，因此更适合作为“这条来源是否有助于回答当前问题（包括支持或反驳某个主张）”“是否需要升级人工”等快速判断节点，不能直接替代负责写回复的 DeepSeek。这里评估的是来源文本对作答的帮助程度，不等于事实正确、来源权威或规则可用于某个组织。官方 API 规格和介绍：<https://docs.typesafe.ai/introduction>、<https://docs.typesafe.ai/api/system-one>、<https://typesafe.ai/blog/introducing-system-one-models-and-jev>。

### 直接 API 基线

使用虚构 K19 内容和 `jev-latest` 发出一次请求，同时询问 4 个判断：是否足以视为正式制度、是否符合真实试点资格、文字是否回答试用问题、是否仍需人工核验。之后对同一状态重复 4 次。服务返回的解析模型名为 `jev-1.14.0`：

- 5 次调用往返耗时：0.713、0.856、0.654、0.639、0.628 秒；平均 0.698 秒，中位数 0.654 秒。
- 5 次结果稳定：正式制度概率 0.02、试点资格概率 0.02、人工核验需要概率 0.99；文字直接回答试用问题的概率在 0.94–0.96。
- 许可证共享边界题单独调用用时 0.707 秒：K19 明确授权共享概率 0.03、足以回答共享许可概率 0.03、应查正式条款/授权人概率 0.96。

### 指标口径校正与新口径复测（2026-11-18）

复核后发现旧字段 `support_probability` 与“可能支持/不支持”的展示标签容易把两个问题混为一谈：来源是否有助于回答，和来源是否支持工单里的某个主张。新实现改用 `answerability_probability` / `likely_answerable`，明确把支持、反驳和限制都视为可能有助于作答的内容；同时不判断来源权威性、制度真实性或能否用于真实试点。历史运行记录保持原值，详情页标为“历史旧口径”，不伪装成新指标或重新计算。

这解释了“自动续期”例子：K19 写的是“到期前复核是否续用”，因此它含有与“不复核自动续期”有关的反证，属于可帮助回答；但它不是正式制度，不能据此断言真实组织禁止或允许自动续期。旧版 #38 记录的 0.92 仍是旧运行结果，不作为新口径的实测值。

|---|---|---:|---:|
