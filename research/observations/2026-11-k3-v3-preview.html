知识正文

适用范围：GitHub.com personal access tokens (classic) 的公开规则。实际处理还要看目标组织是否受企业级策略管理。

classic PAT 默认过期

GitHub 组织 PAT 政策文档说明，classic PAT 没有必须设置过期时间的要求；创建者仍可为单张 token 选择过期日期。因此“没有强制过期要求”不等于“每张 token 都永不过期”。

组织级最大期限

组织 owner 可以为 classic PAT 设置最大有效期，但不能越过企业级上限。如果 token 属于该组织成员且生命周期超过当前组织上限，它会被阻止访问该组织；设置策略本身不会撤销或停用 token。组织级说明说，用户会在调用组织 API 被拒时发现不合规，但没有把某一种恢复步骤规定为所有组织都相同。应核实策略层级、token 类型、所有者/成员关系与具体错误，不要只凭页面显示的到期日下结论。

企业级策略补充

GitHub Enterprise Cloud 的企业政策文档对 classic PAT 另有执行细节：期限会在使用 token 或尝试 SSO 授权时检查；错误会提示用户调整期限，超限时会提示生成符合期限要求的新 token。这是企业级策略说明，不应直接套用到仅由组织配置的策略。先确认该组织是否受企业策略及上级限制。

类型边界与未使用清理

组织/企业资源下 fine-grained PAT 的默认最大有效期为 366 天；这条规则不适用于 classic PAT。个人 PAT 文档中“expires_in 未提供时默认 30 天”的说明位于 fine-grained PAT URL 模板章节，不能据此推断 classic PAT 的默认期限。

GitHub 会因 personal access token 一年未使用而自动撤销/移除它。这是按最近使用时间触发的清理，不等同于 classic PAT 的强制过期要求，也不等同于组织阻止该 token 访问组织。页面仍显示未来的过期日，不足以证明 token 仍存在或仍能访问组织；遇到久未使用的 token，应查看其当前状态与最近使用时间，并让组织 owner 核实当前策略。不要在缺少具体错误信息时断言它一定已被清理或一定需要重新生成。

不要在工单中粘贴 token 明文。
