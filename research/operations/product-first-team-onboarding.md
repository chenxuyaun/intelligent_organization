# 首个团队部署与验收手册

**目标：** 让一个小型客服 / IT 支持团队在独立环境中完成首次登录、两名成员协作、知识复用和数据恢复演练。  
**当前状态：** 操作准备稿；备份/恢复/确认式删除已用独立虚构数据演练，产品模式登录、双成员流程和权限也已用本地模拟 OIDC 提供方做端到端演练。尚未在真实身份提供方、团队或客户环境中执行。  
**部署形态：** 一个客户一套服务进程和数据库；不是共享数据库 SaaS。  
**禁止事项：** 不把 4182/4186 模拟数据库切换为产品库；不把 GitHub 虚构工单当真实业务；未经团队授权，不将真实工单发给模型。

团队负责人和成员要准备第一轮业务讨论时，可先用[第一次团队试用准备卡](team-first-session-worksheet.md)。它不要求先下载制度文件，也不能替代真实的数据授权或脱敏确认。请把“工单保存在团队工作区”和“工单内容发给模型”作为两项决定分别确认。

工作台登录页和首页引导均提供 `/first-session.html` 入口。这是可打印的静态准备卡，不含表单或数据保存功能，不是授权表。

## 1. 谁负责什么

| 角色 | 要准备或确认的事 |
|---|---|
| 团队负责人 | 选定一类重复任务，说明什么算解决、何时升级、哪些数据不能进模型 |
| 身份提供方管理员 | 创建 OIDC Web 客户端，设置回调地址和允许的邮箱声明 |
| 部署运维 | 准备 HTTPS 域名、Node.js、隔离的 `DATA_DIR`、密钥注入方式和备份位置 |
| 首位管理员 | 用已邀请的工作邮箱登录，邀请第二位成员并执行协作验收 |
| 产品维护者 | 观察错误、问题反馈与验收证据；未经授权不接收团队业务数据 |

## 2. 开始前必须具备

- 一个由团队控制的 HTTPS 地址，例如 `https://support.example.com`；Node 服务端口只绑定内网或 `127.0.0.1`，由 TLS 反向代理对外提供 HTTPS。
- 一个支持 OIDC Discovery、Authorization Code、PKCE S256 的身份提供方。登录请求使用 `openid email profile`；ID Token 必须含稳定的 `sub`、邮箱和 `email_verified: true`。
- OIDC 客户端登记的回调地址必须精确为：`https://support.example.com/api/auth/callback`。应用的 `APP_PUBLIC_URL` 只填站点来源，不带路径、查询串或末尾业务路由。
- 一位首位管理员的邮箱，并确认身份提供方对该邮箱返回 `email_verified: true`。
- 一个单独的模型服务账户和密钥。先确认团队允许把所选类别的数据发送给该模型服务；模型密钥仅放在服务端受保护的环境变量/密钥管理器中。
- 一个项目目录之外、只供该团队使用的绝对 `DATA_DIR`。生产服务账号需能读写；其他用户不应能读取数据库或备份。
- 若准备同时部署多个团队，应使用独立主机或至少独立操作系统服务账号和文件权限；不能只靠不同 URL 就认为数据库隔离已经成立。
- 团队书面确认首期任务范围、数据授权人、脱敏规则、知识审核人、保留期限和升级边界。

缺少域名、OIDC 管理员、模型授权或数据负责人时，先停在准备阶段；不要用模拟身份或虚构规则冒充验收。

## 3. 配置与启动

1. 使用 Node.js `22.16.0` 或更高版本；从受控发布包部署代码，安装锁文件依赖：

   ```powershell
   npm ci
   ```

2. 由部署服务管理器设置产品环境变量，不把密钥写进命令历史、浏览器、工单或代码仓库：

   | 环境变量 | 内容 |
   |---|---|
   | `APP_MODE` | `product` |
   | `ORG_NAME` | 团队在工作台看到的名称 |
   | `DATA_DIR` | 项目目录之外的独立绝对路径 |
   | `HOST` / `PORT` | 建议绑定反向代理可访问的内网接口；默认监听 `127.0.0.1:4173` |
   | `APP_PUBLIC_URL` | HTTPS 站点来源，例如 `https://support.example.com` |
   | `OIDC_ISSUER` | 身份提供方在 Discovery 文档中声明的 issuer URL |
| `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` | 专用 Web 客户端凭据；也可把 secret 放在服务器文件中并设置 `OIDC_CLIENT_SECRET_FILE` |
   | `OIDC_BOOTSTRAP_ADMIN_EMAIL` | 首位管理员的已验证邮箱 |
| `MODEL_API_KEY` | 服务端模型密钥；也可把密钥放在服务器文件中并设置 `MODEL_API_KEY_FILE` |
| `MODEL_BASE_URL` / `MODEL_NAME` | 选定的 OpenAI 兼容最终服务地址和模型名；产品模式远程地址必须用 HTTPS，本机回环地址可用 HTTP。地址不能含用户名、密码、查询参数或片段，密钥只放在服务端 `MODEL_API_KEY` / `MODEL_API_KEY_FILE`，也不要把秘密编码进 URL 路径或模型名。模型请求不跟随重定向；如服务返回重定向，应配置最终地址 |

对同一个密钥只能设置直接值或 `_FILE` 路径其中一种。新 Docker 配置用文件挂载；源文件必须由受控运维方式创建，确保容器 UID 1000 可读，并限制宿主机权限。

3. 按 `deploy/nginx-support.example.conf` 准备 TLS 反向代理，替换真实域名和证书路径，先执行 `nginx -t`；检查通过后再 reload。示例将代理指向 Compose 在 `127.0.0.1` 发布的 `HOST_PORT`。OIDC 回调地址必须与 `APP_PUBLIC_URL` 完全一致。启动服务后，日志只用于核对产品模式、监听地址、数据目录、模型名和组织名；不要把包含环境信息的完整日志公开贴出。
4. 从 HTTPS 公网地址检查：
   - `GET /api/health` 返回 HTTP 200，表示进程存活。
   - `GET /api/ready` 返回 HTTP 200，且 `checks.database` 为 `ok`、`checks.modelConfiguration` 为 `configured`。这只说明数据库可读且模型密钥已配置，不证明模型端点可达，也不替代登录检查。
   - 服务启动时会读取 OIDC Discovery；发现文档或客户端配置不可用时，应用不会完成启动。

## 4. 首次登录与成员邀请

1. 没有启用或待邀请管理员时，应用会把 `OIDC_BOOTSTRAP_ADMIN_EMAIL` 建为 7 天有效的待邀请管理员记录。若初始邀请已过期且仍没有管理员，部署运维人员重启服务会重新发出 7 天有效期；服务不会向邮箱发送邮件。该邮箱若已对应停用或非管理员记录，服务会停止启动并提示核对配置，不会自动提升或启用该账号。
2. 管理员打开 HTTPS 站点，点“使用团队账号登录”。登录成功后检查页面显示的邮箱/角色，并确认 `GET /api/auth/me` 返回 `authenticated: true`、`user.role: "admin"`。不要分享该请求中的会话 Cookie。
3. 管理员在“设置 → 团队成员”邀请第二位真实成员，角色先选 `member`。创建后会弹出可复制的邀请消息；管理员需通过团队批准的渠道发送，系统不会代发邮件。被邀请者必须使用与邀请完全相同的已验证邮箱登录，普通成员邀请 7 天后过期。
4. 用独立浏览器配置或另一台设备登录第二位成员，确认其身份和角色与管理员不同。勿复制管理员 Cookie 来模拟第二个人。
5. 回到工作台核对“首条团队学习闭环”引导：进度按两位启用成员、带结果的已解决任务、由不同于来源工单 AI 建议发起者的成员审核发布知识，以及另一成员跨工单引用并记录结果来更新。数据授权始终由团队负责人确认，不会被系统进度自动认定；出现“闭环已记录”只证明这些操作有记录，不证明任务质量或效率已经改善。

登录后，管理员可先在“设置”页查看“新团队开始前”清单：模型配置状态与模型连通性分开显示；管理员可点击“测试模型连接”，服务端只发送固定虚构请求，但服务方可能计费。主模型单次回复最多生成 4096 tokens，可由 `MODEL_MAX_OUTPUT_TOKENS` 调整；产品模式另按团队限制滚动 1 小时请求次数，默认 60 次，可由 `MODEL_MAX_CALLS_PER_HOUR` 调整。建议生成、连接检查和失败请求都会计数；事件只保留操作者、时间、用途和可选工单关联，不保存请求/回复文本或密钥。这些限制不等于费用上限。成员数量只统计启用的管理员和成员账号，不代表他们已实际登录；数据授权、脱敏规则和保留期限仍由团队负责人线下确认，系统不把它们记作自动授权。录单表手工记录数据来源、工作区存储确认人和脱敏状态；只有负责人另行同意把必要内容发给当前模型服务后，管理员才在工单详情登记模型发送确认人。记录绑定到当时的服务端点和模型名称，配置目标变化会拦截后续调用，需负责人重新确认再更新记录。模型调用接口会检查这些记录是否存在及脱敏是否完成；姓名和状态不是身份认证，系统不核实其真实性或脱敏充分性。目标一致不代表服务协议内容未变，部署管理员仍需按实际协议核对模型服务方的数据处理方式。只有负责人确认允许发送、且真实工单已标为“已脱敏”或“无需脱敏”后，才提交真实任务；管理员可清除发送确认记录以阻止后续模型调用。

管理员也可在“设置 → 团队资料”修改工作区显示名称。名称保存在该团队数据库，并进入管理员导出；它不修改 OIDC、域名、数据目录或实例隔离。`ORG_NAME` 仍是数据库中尚无自定义名称时的初始默认值。

## 5. 两名成员的产品验收

使用团队明确批准、已去标识化且风险较低的首期任务；如团队尚未授权模型处理真实数据，使用清楚标注的虚构工单，只能验收产品流程，不能计为业务效果。

| 验收点 | 通过条件 | 证据 |
|---|---|---|
| 身份归属 | 管理员和成员分别登录；工单、审核、成员管理事件显示各自登录身份 | 两个用户各自的页面与事件记录；遮去邮箱等个人信息后留档 |
| 共同任务 | 成员能看到管理员创建并指派给自己的工单，生成组织建议并看到来源 | 工单 ID、运行来源和引用的知识版本；不保存会话令牌 |
| 交接 | 管理员改派给成员并留下摘要；已记录的处理进展与 AI 建议分开显示；接手人能看到人工审核后实际采纳的原稿或修订稿；当前接手人能确认，非接手人不能确认 | 工单时间线中的处理进展、交接创建/接收者/接收时间；交接摘要与审核记录中的采纳内容一致，不把未执行建议写成已执行动作 |
| 知识治理 | 成员提交经验草稿；有权限的人审核；发布版本进入后续组织检索；到期知识退出检索并出现在“过期待复核”，复核者可按原因停用 | 卡片来源、范围、审核人和版本；驳回草稿不得被检索；过期卡不能出现在新建议检索来源中 |
| 结果闭环 | 完成任务时记录实际结果、返工/升级或重开事实；复盘页明确样本量和时间范围 | 已处理任务及复盘页截图/脱敏导出 |
| 只读权限 | `viewer` 可查看但不能写工单、审核、发布知识或改成员 | 页面检查及一次被服务端拒绝的写操作；不借用他人账号 |
| 工作区隔离 | 若验收另一团队，使用另一独立部署、域名、凭据和 `DATA_DIR`；不得把多团队放进同一实例或数据库 | 两个环境的非敏感配置摘要；确认服务账户不能读取另一团队目录 |
| 数据保护 | 新工作区没有 sample 记录；管理员导出可用；备份校验通过；恢复到全新目录可读 | 脱敏的计数、校验结果和恢复目录；不覆盖当前工作区 |

**阶段性通过：** 身份、共同任务、交接、知识治理和结果记录均通过，且备份恢复演练完成。任何权限错误、跨团队数据暴露、未授权模型发送或错误身份归属都判定失败并暂停试用。

**业务效果不是本次部署验收：** 至少连续观察一段真实任务后，才比较质量、返工、解决周期、交接等待和经验迁移；样本太少时只报告观察事实，不宣称提效或因果关系。

### 2026-11-19 隔离备份恢复演练

- 在系统临时目录新建隔离应用副本与 SQLite 数据库，只写入虚构成员、工单、运行、知识卡、反馈和临时认证记录；未读取 `.env`，未连接模型，未启动正式服务，未触碰项目 `data` 或 4182/4186 样本数据库。
- `backup`、`verify`、`restore` 均成功。备份与恢复后工单、运行、知识卡、成员、反馈各 1 条；SHA-256 与 SQLite 完整性校验通过。恢复库不含会话及 OIDC 临时流程，源库仍保留它们；两库完整性均为 `ok`。
- 随后对源数据目录运行带 `--service-stopped` 和规范路径精确确认词的 `erase`。命令删除了源库 `app.db`，保留 `DATA_DIR` 目录、独立备份目录和恢复库；删除后备份复验仍通过。追加在独立副本上的锁演练确认：活跃 PID 锁会让 erase 拒绝且保留数据库与锁；已退出 helper PID 的陈旧锁会随 app.db 删除。未在真实团队数据或 product 服务实际锁生命周期上执行。
- 随后将备份再恢复到独立副本，向副本写入虚构 OIDC subject、会话 hash 和登录 flow，通过本机临时 HTTP listener 调用实际 `/api/admin/export` 路由。未登录返回 401、普通成员返回 403、错误 Origin 返回 403、管理员返回 200；导出 JSON 含虚构工单/运行/知识/反馈和 `workspace_exported` 事件，但没有 subject、会话 hash 或 flow 凭据，原库认证行保持不变。管理员身份和 Origin 校验由测试替身提供，因此这验证的是导出路由、序列化与路由权限分支，不是 OIDC 登录、真实 CSRF 身份链或浏览器下载验收。测试副本的数据库随后按精确确认词删除。
- 同一临时库还通过应用实际存储与检索函数验证知识停用：已批准的发布卡停用前能命中，停用后不再被检索；`retire` 审核和操作者事件已写入，已有引用记录保留。没有覆盖真实 product HTTP 身份/CSRF/浏览器路径。演练目录仍在 `C:\Users\yuesh\AppData\Local\Temp\io-product-ops-drill-dvzUbi`；平台拦截了递归清理命令，目录只含虚构数据和临时应用副本，待手动清理。

### 2026-11-19 本地模拟 OIDC 双成员端到端演练

- 从当前代码复制出临时应用目录，配置独立空 `DATA_DIR`；应用通过本机 HTTPS 反向代理访问，并连接一个本地自签名 HTTPS OIDC 模拟提供方。没有 `.env`；仅设置不具备真实权限的模拟模型密钥，未调用模型。
- 使用真实 `openid-client` 库执行 discovery、Authorization Code、PKCE 和 ID Token 验证；模拟提供方用 RSA 私钥签名，token endpoint 校验 code verifier。5 次授权码交换覆盖管理员、未邀请用户、受邀成员、`email_verified=false` 用户和 viewer。state、nonce、PKCE、签名、issuer/audience 检查均由真实客户端库执行；应用只激活受邀且邮箱已验证的账号。
- 产品实例 ready 200；页面、app.js、CSP/HSTS、Secure/HttpOnly/SameSite/Path Cookie 均通过本机 HTTPS 请求检查。管理员邀请成员；管理员创建虚构工单并指派，成员可见；管理员准备交接，管理员本人确认被拒、当前接手成员确认成功；缺少结果说明时不能结案，补充虚构结果后团队复盘显示 1 已解决、1 有结果、1 次已接收交接。
- viewer 创建工单和导出均被服务端拒绝；错误 Origin 写请求被拒。管理员 JSON 导出成功，包含业务事件、不包含 OIDC subject、会话 Cookie/token hash 或登录 flow。停用成员撤销其现有会话，登出撤销会话；未邀请及邮箱未验证用户均不能得到会话。
- 第二实例因活跃工作区锁而启动失败，首实例健康状态不变；正常关机释放锁。SQLite `integrity_check=ok`，全部测试用户登出后会话及 OIDC flow 均为 0。除一个直接写入的 `synthetic_fixture` 交接运行外，无 AI 运行或模型请求。隔离数据库随后经 `workspace-data.js erase` 删除。
- **边界：** 本地 OIDC 提供方是模拟件，未验证客户使用的真实 IdP、真实域名/反向代理设置、图形浏览器 Cookie 行为、邀请邮件或真实业务流程。此结果证明产品链路可在受控本地环境运行，不证明生产安全或业务成效。

### 2026-11-19 双实例数据隔离演练

- 使用同一份当前服务代码启动两个独立 product 进程，各自配置不同的 `DATA_DIR`、组织名、内部端口和本机 HTTPS 入口；核心服务文件哈希与工作区源文件相同。两个实例都连接本地模拟 OIDC Discovery 提供方，没有调用 token endpoint 或模型。
- 为隔离检查，在两个独立数据库里建立相同邮箱和 OIDC subject 的虚构启用成员，并分别写入不同的模拟会话 token hash。A 的会话在 A 通过，在 B 的 `/api/auth/me` 返回未登录、访问受保护工单接口返回 401；B 的会话反向访问 A 也同样被拒绝。
- 分别通过各自 HTTP API 创建唯一虚构工单。每个实例的工单列表、组织名和管理员 JSON 导出只包含自己的记录，且本地 ID 相同也不会显示另一方标题。两库 `integrity_check=ok`；分别登出后两库会话数为 0；正常关机释放两个独立 `app.lock`。

## 6. 失败与回退

- 登录失败：暂停成员录入和任务处理；核对 issuer、回调地址、客户端类型、邮箱大小写和 `email_verified`。不要临时关闭验证或放开自助注册。
- HTTPS/Cookie 异常：检查浏览器实际使用 HTTPS、反向代理证书及 `APP_PUBLIC_URL`；不要把 `Secure` Cookie 改成非安全 Cookie。
- 数据库或模型错误：保存不含密钥/个人数据的错误摘要；不要切到演示模式继续处理客户任务。
- 升级失败：先停止服务，恢复到变更前的代码版本；数据恢复到新目录并核对后再切换 `DATA_DIR`，原目录先保留。
- 删除工作区：遵循 README 的确认式删除步骤。异常退出留下 `app.lock` 时，先核对锁内 PID 确实不存在；删除命令会校验并一起移除陈旧锁。若要重启而非删除，才在确认后手工清理锁。不得仅凭端口检查失败就认定无进程。

## 7. 现阶段不能承诺的能力

- 没有自助注册、邀请邮件、多租户共享数据库、持续告警或自动升级回滚。
- 当前 OIDC 已与本地模拟提供方做端到端演练，尚未和真实身份提供方做端到端验证；双实例数据与会话隔离已在独立 DATA_DIR 中演练，操作系统目录权限/服务账号隔离仍待部署验收；这份手册也不是安全评审。
- 管理员备份文件本身不加密；备份介质、云端快照、密钥轮换和数据保留/彻底清理由部署方另行管理。
- `/api/ready` 不会调用模型，也不会检查模型端点当前是否可达。
- 没有真实团队连续任务数据前，不能宣称组织效率或服务质量提升。
