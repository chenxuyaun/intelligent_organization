# 第一次团队试用：一页准备卡

这张卡是团队开会时一起填的，不需要先下载制度文件，也不要求大家先懂 AI。它用来把“先试一个问题”变成一件可负责、可复盘的工作。

**注意：** 本卡不是公司政策、法律意见或模型数据授权。团队要分别确认真实工单能否保存在工作区，以及必要内容能否发给模型。未确认本地存储规则前，不要把真实工单录入产品。需要看界面时，使用与正式团队数据隔离的虚构预览环境。

## 4. 先确定数据边界

由团队负责人回答；不清楚时先暂停真实数据试用。存入工作区与发送给模型是两项不同的决定。

- 哪位负责人确认本轮数据可以发送给所选模型服务：
- 管理员会在哪条工单上记录这项确认：
- 哪些信息不能录入或发送（例如密码、访问令牌、客户身份信息）：
- 需要怎样去掉或替换敏感信息：
- 任务和模型记录由谁查看、计划保留多久：
- 发生模型答错、数据不适用或需要人工升级时，联系谁：

这张卡只记录讨论结果，不代表系统能检查授权是否真实、脱敏是否充分或保留期限是否合规。负责人确认可以发送后，管理员还需在对应工单详情里单独记录模型发送确认人；清除该记录会阻止后续模型调用。产品的单次输出与请求次数上限也不等于费用上限。

## 5. 完成两件相似任务后一起回看

第一件任务记录实际结果；如果有值得复用的处理经验，由另一位成员审核后再发布。第二件相似任务由另一位成员处理，观察团队知识是否真的被找到、引用，并帮助完成任务。

| 观察项 | 第一件任务 | 第二件任务 |
|---|---|---|
| 任务是否解决，依据是什么 |  |  |
| AI 建议被采纳、修改还是拒绝；为什么 |  |  |
| 是否返工、重开或升级 |  |  |
| 共享经验是否被引用；它改变了哪一步（如果有） |  |  |
| 还需要改哪条步骤或知识 |  |  |

两件任务只能帮助团队检查流程是否跑通，不能证明效率或质量已经提升。继续积累一段时间的真实任务后，再看质量、返工、解决周期和交接情况，并说明样本范围与可能的其他影响因素。
