# IO-002：模型发送确认闸门

**状态：** 实现完成；隔离只读界面预览已核对；真实产品实例验收待做。  
**目标：** 真实试点工单只有在团队确认本地存储、完成脱敏，并同意把必要内容发给当前模型服务后，才允许调用模型。  
**负责人：** 用户负责真实团队的业务规则与授权决定；AI 负责实现、静态复核和证据记录。  
**输入依据：** 用户提供的项目 `AGENTS.md` 数据边界规则；`research/06-product-v1-definition.md` 的单团队试用方向；团队负责人对具体模型服务的真实决定（当前尚无客户授权材料）。

## 完成条件

- 旧工单不从原有“授权人”姓名推断模型发送授权，迁移后保持未确认。
- 模型调用服务端检查来源、工作区存储确认、脱敏、模型发送确认四项；前端按钮只作提示，服务端负责拦截。
- 模型发送确认由管理员登记并留事件；确认绑定到登记时的服务端点和模型名称，配置目标变化后旧记录失效。
- 成员能看懂确认状态；管理员能看当前/已确认目标，并能在负责人重新确认后更新记录或撤销。
- 实现证据与真实组织授权、产品成效分开记录。

## 已完成

- `tickets` schema 与幂等迁移增加模型确认人、服务端点和模型名称列；默认值为空。
- 建单时仅管理员可以登记；工单详情新增管理员更新/撤销入口；事件流展示人工操作与操作者。
- 发送确认变更事件保存前后端点/模型快照；页面时间线显示旧目标到新目标，撤销时显示被撤销的目标。不保存密钥或确认人姓名到事件载荷。
- `POST /api/tickets/:id/run` 前的 `pilotRunGate` 检查确认记录及当前模型目标；不匹配时返回阻拦原因。
- `MODEL_BASE_URL` 启动配置只接受不含用户名、密码、查询参数或片段的 HTTP(S) 地址；密钥必须单独由服务端 `MODEL_API_KEY` 或 `MODEL_API_KEY_FILE` 提供，避免模型目标被展示或写入事件历史时意外暴露 URL 凭证。
- 产品模式远程模型端点强制 HTTPS；仅 `localhost`、`127.0.0.0/8` 和 `::1` 回环地址可用 HTTP，以支持同机本地模型服务而不允许远程明文传输。
- 主模型和 TypeSafe 请求都拒绝 HTTP 重定向，避免模型请求正文被转发到确认目标以外的主机；模型错误响应正文不再回传给成员，避免服务商错误页意外回显任务内容。
- 产品定义、README、首次团队手册和试点闭环页面同步显示目标绑定及验证边界。
- `node --check` 对以下 7 个 JavaScript 文件通过：`server/api.js`、`server/store.js`、`server/db.js`、`server/data-scope.js`、`server/pilot-loop.js`、`public/app.js`、`research/scripts/preview-onboarding-progress.mjs`。
- 只读预览 `http://127.0.0.1:4193/` 当前 PID `121680`，三种虚构状态均返回 HTTP 200：未确认拦截、目标匹配放行、旧目标不匹配拦截；旧目标事件显示历史端点，详情页显示当前端点。该预览没有产品数据库、真实登录、模型调用或写入；所有非 GET 请求由预览服务拒绝。停止命令：`Stop-Process -Id 121680`。

## 边界与未完成

- 手填负责人姓名不是身份认证或授权证明；系统不能据此证明负责人真的同意。团队仍需通过自己的流程确认模型服务的数据处理条款。
- URL 与模型名称匹配不代表服务商协议、留存政策或部署配置外部状态没有变化。
- URL 凭证校验仅防止常见的 userinfo/query/fragment 泄漏；部署者仍不得把密钥或其他敏感信息编码进路径、主机名或模型名称。
- 本轮未读 `.env` 或凭证、未访问产品数据库、未调用模型、未运行自动化测试、未重启产品实例。
- 真实产品数据库尚未应用迁移，服务端硬闸门尚未在该实例上生效。旧工单需要负责人实际确认后，由管理员逐单重新登记；模型目标变更时也需重新确认。
- 后续验收应在独立的虚构 product 工作区核对迁移幂等、管理员/成员权限、CSRF、目标匹配/不匹配拦截及撤销；通过后再由真实团队负责人决定是否开始真实数据试用。任何虚构验收均不算客户验证或组织成效。
